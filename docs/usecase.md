## UC-01. 서비스 접속 및 접근 권한 확인

| 항목 | 내용 |
| --- | --- |
| 목적 | 인증 상태에 맞는 페이지 제공 |
| 주요 액터 | 비회원, 회원 |
| 보조 액터 | 인증 시스템 |
| 트리거 | 서비스 URL 접속 |
| 사전조건 | 웹 애플리케이션 접근 가능 |
| 사후조건 | 인증 상태에 맞는 페이지 표시 |
| 우선순위 | P0 |

### 기본 흐름

1. 사용자가 서비스 URL에 접속한다.
2. 시스템이 현재 인증 상태를 확인한다.
3. 비회원에게는 공개 랜딩 페이지를 보여준다.
4. 회원에게는 개인 홈 대시보드를 보여준다.
5. 사용자가 Top Bar에서 접근 가능한 메뉴를 선택한다.
6. 시스템이 해당 페이지로 이동시킨다.

### 대체 흐름

- **A1**: 비회원이 회원 전용 URL 접근 → 로그인 페이지로 이동
- **A2**: 로그인 상태에서 로그인 페이지 접근 → 홈 대시보드로 이동
- **A3**: 세션 만료 → 재로그인 요구
- **A4**: 존재하지 않는 URL → 404 안내 화면

### 비즈니스 규칙

- **비공개 기본**: 개인 기록은 비공개가 기본값
- **서버 검증**: 메뉴 숨김만으로 권한 처리하지 않고, 서버·데이터 접근 단계에서 검증

## UC-02. 회원가입

| 항목 | 내용 |
| --- | --- |
| 목적 | 신규 계정 생성 |
| 주요 액터 | 비회원 |
| 보조 액터 | 인증 시스템, 데이터베이스 |
| 트리거 | 회원가입 버튼 클릭 |
| 사전조건 | 비로그인 상태 |
| 사후조건 | 계정 생성 완료 |
| 우선순위 | P0 |

### 기본 흐름

1. 사용자가 `/signup`에 접속한다.
2. 시스템이 회원가입 폼을 표시한다.
3. 사용자가 이메일을 입력한다.
4. 비밀번호와 비밀번호 확인을 입력한다.
5. 필수 약관이 있다면 동의한다.
6. 회원가입 버튼을 클릭한다.
7. 시스템이 이메일 형식·필수값·비밀번호 일치 여부를 검증한다.
8. 인증 시스템에 계정 생성을 요청한다.
9. 인증 시스템이 계정을 생성한다.
10. 시스템이 가입 완료 안내를 표시한다.
11. 인증 정책에 따라 로그인 또는 이메일 확인 절차로 이동한다.

### 대체 흐름

- **A1 이메일 형식 오류**: 해당 입력 필드에 한국어 오류 표시
- **A2 비밀번호 불일치**: 비밀번호 확인 항목에 오류 표시
- **A3 이미 등록된 이메일**: 인증 정책상 허용되는 범위에서 가입 불가 안내
- **A4 가입 요청 실패**: 재시도 안내
- **A5 이메일 확인 필요**: 확인 완료 전까지 보호된 서비스 접근 제한

### 비즈니스 규칙

- **식별 수단**: 이메일을 회원 식별·인증에 사용
- **비밀번호**: 안전한 인증 제공자를 통해 처리, 별도 DB 테이블에 평문 저장 금지
- **완료 구분**: 계정 생성 완료와 로그인 완료는 별개

### UI 고려사항

- 비밀번호 표시·숨기기 토글
- 필드별 오류 메시지
- 처리 중 중복 제출 방지
- 로그인 페이지 이동 링크

## UC-03. 로그인 및 로그아웃

| 항목 | 내용 |
| --- | --- |
| 목적 | 회원 인증 및 세션 관리 |
| 주요 액터 | 회원 |
| 보조 액터 | 인증 시스템 |
| 사전조건 | 가입된 계정 존재 |
| 사후조건 | 세션 생성 또는 종료 |
| 우선순위 | P0 |

### 로그인 기본 흐름

1. 회원이 `/login`에 접속한다.
2. 이메일과 비밀번호를 입력한다.
3. 로그인 버튼을 클릭한다.
4. 시스템이 필수 입력값을 검증한다.
5. 인증 시스템이 자격 증명을 확인한다.
6. 성공 시 세션을 생성한다.
7. 시스템이 로그인 상태를 갱신한다.
8. 홈 대시보드 또는 원래 접근하려던 페이지로 이동한다.

### 로그아웃 기본 흐름

1. 회원이 로그아웃 버튼을 클릭한다.
2. 시스템이 로그아웃을 요청한다.
3. 인증 세션을 종료한다.
4. 회원 전용 데이터의 화면 표시를 초기화한다.
5. 공개 랜딩 페이지로 이동한다.

### 예외 처리

- **로그인 실패**: 잘못된 정보 입력 시 "로그인 정보를 확인해 주세요." 표시
- **네트워크 오류**: 재시도 안내
- **세션 만료**: 보호된 작업 시도 시 재인증 안내
- **뒤로 가기**: 로그아웃 후에도 보호된 데이터가 다시 노출되지 않아야 함

## UC-04. 취미 카테고리 조회

| 항목 | 내용 |
| --- | --- |
| 목적 | 범용 분류 체계에서 취미 선택 |
| 주요 액터 | 회원 |
| 트리거 | 카테고리 선택 UI 접근 |
| 사전조건 | 초기 카테고리 목록 제공 가능 |
| 사후조건 | 유효한 취미 선택 완료 |
| 우선순위 | P0 |

### 기본 흐름

1. 회원이 기록 작성 페이지에 접근한다.
2. 시스템이 취미 대분류 목록을 표시한다.
3. 회원이 대분류를 선택한다.
4. 시스템이 해당 대분류의 세부 취미를 표시한다.
5. 회원이 세부 취미를 선택한다.
6. 시스템이 선택값을 기록 폼에 반영한다.

### 대체 흐름

- **대분류 변경**: 기존 세부 취미 선택값 초기화
- **세부 항목 없음**: 안내 표시
- **'기타' 선택**: 초기 버전 규칙에 따라 일반 기타 항목 선택
- **직접 생성 불가**: 신규 카테고리 생성 기능 미제공

### 비즈니스 규칙

- **관계 일관성**: 대분류와 세부 취미는 일관된 관계 유지
- **기록 보존**: 카테고리명이 바뀌어도 과거 기록 유지
- **초기 분류**: PRD에서 정의한 9개 대분류 사용

## UC-05. 취미 기록 작성

| 항목 | 내용 |
| --- | --- |
| 목적 | 취미 경험 기록 |
| 주요 액터 | 회원 |
| 보조 액터 | 데이터베이스 |
| 트리거 | '기록하기' 클릭 |
| 사전조건 | 로그인 완료, 작성 페이지 접근 가능, 저장 서비스 정상 |
| 사후조건 | 본인에게 귀속된 기록 생성, 새로고침·재로그인 후에도 조회 가능 |
| 우선순위 | P0 |

### 기본 흐름

1. 회원이 기록하기 버튼을 클릭한다.
2. `/activities/new`로 이동한다.
3. 시스템이 빈 작성 폼을 제공한다.
4. 활동 날짜를 선택한다.
5. 취미 대분류와 세부 취미를 선택한다.
6. 기록 제목을 입력한다.
7. 활동 내용을 입력한다.
8. (P1) 감정 이모지를 선택한다.
9. (P1) 만족도를 입력한다.
10. (P1) 사진을 첨부한다.
11. 저장 버튼을 클릭한다.
12. 시스템이 필수 입력값을 검증한다.
13. 인증된 사용자의 기록 생성 요청을 처리한다.
14. 데이터베이스가 기록을 저장한다.
15. 저장 완료 결과를 반환한다.
16. 기록 상세 페이지로 이동한다.
17. 새 기록이 목록과 대시보드에 반영된다.

### 필수 / 선택 입력

- **필수**: 활동 날짜, 대분류, 세부 취미, 제목, 내용
- **선택**: 감정, 만족도, 사진

### 대체 흐름

- **A1**: 감정·만족도·사진 없이 저장 가능
- **A2**: 같은 날짜에 여러 기록 작성 가능
- **A3**: 저장 없이 이탈하면 기록 미생성
- **A4**: 저장 요청 중 버튼 비활성화로 중복 제출 방지

### 사후조건 상세

- **성공 시**: 기록 생성, 현재 회원에 귀속, 재조회 가능
- **실패 시**: 불완전한 기록이 저장 완료로 표시되지 않음, 입력 내용은 가능한 유지

### 예외 처리

| 코드 | 조건 | 처리 |
| --- | --- | --- |
| E-01 | 필수값 누락 | 항목별 오류 표시 |
| E-02 | 공백만 입력 | 유효하지 않은 값으로 처리 |
| E-03 | 인증 만료 | 로그인 안내 |
| E-04 | DB 저장 실패 | 저장 실패 메시지 및 재시도 |
| E-05 | 중복 클릭 | 중복 기록 생성 방지 |

## UC-06. 아카이브 목록 조회·필터·정렬

| 항목 | 내용 |
| --- | --- |
| 목적 | 개인 활동 이력 탐색 |
| 주요 액터 | 회원 |
| 트리거 | Top Bar에서 아카이브 선택 |
| 사전조건 | 로그인 완료 |
| 사후조건 | 조건에 맞는 본인 기록 목록 표시 |
| 우선순위 | P0 |

### 기본 흐름

1. 회원이 `/activities`에 접근한다.
2. 시스템이 현재 사용자를 확인한다.
3. 접근 권한이 있는 기록만 조회한다.
4. 활동 날짜 기준 최신순으로 카드 목록을 표시한다.
5. 회원이 카테고리 필터를 선택한다.
6. 시스템이 해당 카테고리의 기록만 표시한다.
7. 회원이 정렬 방식을 변경한다.
8. 목록 순서가 바뀐다.
9. 기록 카드를 클릭하면 상세 페이지로 이동한다.

### 대체 흐름

- **기록 없음**: 첫 기록 작성 CTA 제공
- **필터 결과 없음**: 결과 없음 안내
- **전체 보기**: 필터 초기화
- **같은 날짜**: 등록 시각 등 일관된 보조 정렬 기준 적용

### 비즈니스 규칙

- **본인 기록만**: 목록에는 본인 기록만 표시
- **필터+정렬 동시 작동**: 카테고리 필터와 날짜 정렬 병행
- **빈 값 허용**: 사진·감정이 없는 기록도 카드로 표시

## UC-07. 기록 상세 조회

| 항목 | 내용 |
| --- | --- |
| 목적 | 경험의 전체 내용 확인 |
| 주요 액터 | 회원 |
| 트리거 | 기록 카드 선택 |
| 사전조건 | 로그인 및 기록 접근 권한 |
| 사후조건 | 상세 정보 표시 |
| 우선순위 | P0 |

### 기본 흐름

1. 회원이 기록 카드를 클릭한다.
2. `/activities/[id]`로 이동한다.
3. 시스템이 인증 상태를 확인한다.
4. 기록 존재 여부와 접근 권한을 확인한다.
5. 날짜, 카테고리, 제목, 내용을 표시한다.
6. 저장된 경우 감정, 만족도, 사진을 표시한다.
7. 수정하기·삭제하기 버튼을 제공한다.

### 대체 흐름

- **없는 기록**: "요청한 기록을 찾을 수 없어요." 안내

- **사진 없음**: 텍스트 중심 레이아웃 유지
- **감정·만족도 없음**: 해당 영역 숨김 또는 미입력 표시

### 비즈니스 규칙

- **ID 변조 방지**: URL의 기록 ID를 임의 변경해도 타인 기록은 조회 불가
