## 1. 디자인 시스템 개요

### 1.1 핵심 경험

HOBBY LOG는 **취미 캘린더 × 사진 일기 × 감정 기록 × 개인 아카이브**다. 화면은 기록을 재촉하거나 성과를 경쟁시키지 않는다. 대신 사용자가 지난 취미의 순간을 편안하게 돌아보고, 한 번의 기록도 의미 있는 "새잎"처럼 느끼게 한다.

### 1.2 디자인 원칙

1. **Calm — 정보보다 여백이 먼저 보이게**
   화면당 핵심 행동은 1개로 제한하고, 카드 간격과 넉넉한 패딩으로 호흡을 만든다.
2. **Playful — 작은 반응으로 즐거움을 주기**
   감정 이모지, 취미 아이콘, 새잎·물방울 모티프를 포인트로만 사용한다.
3. **Minimal — 장식보다 기록이 중심**
   그림자·테두리·색을 동시에 강하게 쓰지 않는다. 기본은 밝은 표면과 명확한 위계다.
4. **Botanical — 기록의 누적을 성장으로 번역**
   횟수는 단순 숫자뿐 아니라 씨앗 → 새싹 → 잎 → 작은 정원의 단계로 보여준다.
5. **Accessible — 차분함이 낮은 대비를 뜻하지 않게**
   본문·버튼·상태는 WCAG AA 수준의 대비를 목표로 하고, 색 외 텍스트·아이콘을 함께 쓴다.

## 6. 핵심 컴포넌트

### 6.1 버튼

| 유형 | 스타일 | 사용 |
| --- | --- | --- |
| Primary | primary-700 배경, 흰색 글자 | 저장, 기록하기 |
| Secondary | 흰색, primary-300 테두리 | 취소, 이전 |
| Tertiary | 배경 없음, primary-700 글자 | 보조 이동 |
| Destructive | error 배경 또는 error 텍스트 | 삭제 확인 |
| Floating CTA | 원형/캡슐, 그림자 1단계 | 모바일 새 기록 |

높이 44px 이상, 모바일 터치 영역 48px 이상. 로딩 중에는 중복 클릭을 막고 "저장 중…"을 표시한다.

### 6.2 기록 카드

- 사진 비율 4:3 또는 1:1 중 목록 단위로 통일
- 제목 2줄 말줄임, 날짜·카테고리·감정·만족도 노출
- 사진이 없으면 카테고리별 단색 배경 + 선 아이콘
- 전체 카드가 클릭 영역이되, 수정·삭제 메뉴는 별도 접근 이름 제공
- Hover: 2px 위로 이동 + 그림자. Touch: 배경색 변화만 적용

### 6.3 입력 필드

- 라벨은 입력창 바깥 위에 유지하고 placeholder로 대체하지 않는다.
- 오류는 필드 아래 한 줄 설명 + error 아이콘 + 테두리로 표현한다.
- 날짜, 카테고리, 세부 취미, 제목, 내용이 필수임을 명확히 표시한다.
- 작성 실패 시 입력값과 업로드 미리보기를 보존한다.

### 6.4 취미 칩

아이콘 + 텍스트 조합. 기본은 neutral, 선택은 secondary-200 배경 + primary-800 텍스트 + 체크 표시. 여러 개 선택 시 제거 버튼에 접근 이름을 부여한다.

### 6.5 감정 선택기

😆 신남 · 🥰 행복 · 😌 평온 · 😎 뿌듯 · 😐 보통 · 😴 피곤 · 😢 슬픔 · 😤 답답함.
가로 스크롤 대신 모바일에서 4×2 그리드 사용. 선택된 감정은 링·배경·텍스트 세 가지로 구분한다.

### 6.6 만족도

별 1~5개 + "1점/5점" 읽기 라벨. 감정과 별도 섹션으로 배치하며 선택 취소가 가능해야 한다.

### 6.7 캘린더

- 오늘: 얇은 primary 링
- 선택일: primary-700 채움 + 흰색 날짜
- 기록일: 하단 점 또는 작은 감정 표시
- 같은 날 여러 기록: 최대 3개 점 + "+N"
- 키보드 방향키 이동, 월 이동 버튼, 현재 월 텍스트 제공

### 6.8 피드백·상태

- Toast: 저장·수정 완료 등 가벼운 결과, 4초 이내
- Inline error: 필드 오류
- Alert dialog: 삭제·로그아웃 등 되돌리기 어려운 행동
- Skeleton: 카드 구조와 동일한 로딩
- Empty state: 식물 선 일러스트 + 상황 설명 + 다음 행동 1개

## 8. 페이지별 디자인

### 8.1 랜딩 / 로그인 후 홈 · `/`

**목적:** 비회원에게 가치 제안, 회원에게 오늘의 기록 진입점 제공.

- 비회원: "좋아하는 순간을 기록하고, 나만의 취미 역사를 쌓다" + 시작하기 + 기록 예시 카드
- 로그인 회원: 인사말, 이번 달 활동 횟수, 최근 기록, 미니 캘린더, 큰 "오늘 기록하기" 카드
- 가장 큰 밝은 그린 카드 1개에 핵심 CTA 배치
- Mobile: 통계 카드를 2열, 최근 기록을 가로 스크롤 없이 1열

### 8.2 로그인 · `/login`

**목적:** 최소 단계로 안전하게 복귀.

- 이메일, 비밀번호, 로그인, 회원가입 링크
- 오류 메시지는 "이메일 또는 비밀번호를 확인해 주세요"
- 카드 1개 구조, 불필요한 일러스트 제거
- Mobile에서 키보드가 CTA를 가리지 않도록 스크롤 여유 확보

### 8.3 회원가입 · `/signup`

**목적:** 계정 생성 후 취미 설정으로 자연스럽게 연결.

- 이메일, 비밀번호, 비밀번호 확인, 동의, 가입
- 조건은 입력 전부터 간단히 표시
- 완료 후 `/onboarding` 이동
- 단계 수를 상단에 "1 / 2 계정 만들기"로 표시

### 8.4 취미 설정 · `/onboarding`

**목적:** 관심 취미를 복수 선택하되 건너뛸 수 있게 함.

- 대분류 섹션 + 아이콘 취미 칩
- 선택 개수 안내, 검색은 후속 기능
- 하단 고정 CTA "선택 완료", 텍스트 버튼 "나중에 할게요"
- Mobile 2열, Tablet 3열, Desktop 4~5열

### 8.5 캘린더 · `/calendar`

**목적:** 날짜별 취미와 감정을 빠르게 회고.

- 월 전환 + 월간 그리드 + 선택 날짜의 기록 목록
- Desktop: 8:4 분할, Mobile: 캘린더 아래 바텀시트/목록
- 날짜 셀은 44px 이상, 한 날짜의 기록이 많아도 셀 높이가 흔들리지 않게 함
- 빈 날짜 선택 시 "이 날의 첫 기록을 남겨보세요"

### 8.6 아카이브 · `/activities`

**목적:** 기록을 최근순으로 탐색하고 필터링.

- 상단 제목·기록 수·기록하기
- 카테고리 칩, 날짜 정렬, 초기화
- Desktop 3열, Tablet 2열, Mobile 1열
- 필터 결과 0건은 현재 필터를 보여주고 "필터 초기화" 제공

### 8.7 기록 작성 · `/activities/new`

**목적:** 최소 필수 정보로 빠르게 저장.

- 1단계 기본 정보: 날짜·취미·제목
- 2단계 순간 기록: 내용·감정·만족도·사진
- Desktop: 폼 + 우측 미리보기, Mobile: 단일 컬럼
- 하단 저장 CTA는 화면에 안정적으로 접근 가능하되 내용은 가리지 않음
- 실패 시 입력값 유지, 성공 시 상세 화면으로 이동

### 8.8 기록 상세 · `/activities/[id]`

**목적:** 사진과 감정을 중심으로 한 편의 일기처럼 회고.

- 상단 사진, 제목, 날짜, 취미, 감정·만족도, 본문
- 수정/삭제는 더보기 메뉴에 모으되 숨기지 않음
- 이전/다음 기록 이동은 후속 옵션
- 사진이 없을 때는 과도하게 큰 빈 공간을 만들지 않음

### 8.9 기록 수정 · `/activities/[id]/edit`

작성 화면과 같은 컴포넌트를 재사용한다. 기존 값을 모두 채우고, 변경사항이 있을 때 이탈하면 확인 창을 표시한다. 삭제는 수정 폼 하단이 아니라 별도 메뉴에서 다룬다.

### 8.10 마이페이지 · `/mypage`

**목적:** 계정·관심 취미·누적 기록을 관리.

- 프로필 요약, 전체 기록 수, 관심 취미, 로그아웃
- 개인정보·계정 삭제는 명확히 분리된 위험 영역
- 향후 성장 정원 진입 카드 배치 가능
- Mobile에서는 설정 목록을 1열로 단순화

## 9. 인터랙션 패턴

- **Hover:** 150ms ease-out, 위치 변화 최대 2px
- **Press:** 80ms, scale 최소 0.98. 과도한 튕김 금지
- **Page transition:** 180~220ms opacity + 4px 이동
- **Modal:** 배경 dim 32%, focus trap, ESC 닫기
- **Optimistic UI:** 저장 성공이 확실한 단순 토글만 적용. 기록 저장은 서버 응답 후 완료 처리
- **Reduced motion:** 운영체제 설정 시 위치 이동·성장 애니메이션 제거
- **Undo:** 가능하면 삭제 후 5초 되돌리기 제공. 불가능하면 사전 확인 필수
- **Keyboard:** Tab 순서가 시각적 순서와 일치하고 focus ring을 숨기지 않는다.

## 10. 반응형 기준

| 이름 | 시작점 | 핵심 변화 |
| --- | --- | --- |
| mobile | 320px | 4열, 20px 여백, 하단 탭, 단일 컬럼 |
| tablet | 768px | 8열, 32px 여백, 2열 카드, 축약 내비 |
| desktop | 1024px | 12열, 사이드바, 3열 카드, 캘린더 분할 |
| wide | 1440px | 콘텐츠 max 1200px 유지, 여백 확대 |

### 세부 규칙

- 320~767px: 카드 패딩 16~20px, 표는 카드/리스트로 전환
- 768~1023px: 사이드바는 아이콘 중심, 폼은 최대 720px
- 1024~1439px: 기본 데스크톱
- 1440px 이상: 글줄과 카드가 과도하게 늘어나지 않도록 max-width 유지
- 모바일 가로 스크롤은 사진 캐러셀 외 금지
- 중요 CTA는 엄지손가락이 닿는 하단 영역을 우선

## 11. 향후 콘셉트 · 성장 정원

### 11.1 목표

기록 횟수를 경쟁적 점수 대신 **돌봄과 성장의 서사**로 보여준다. 정원은 사용자를 압박하지 않고, 쉬어도 시들거나 패널티를 주지 않는다.

### 11.2 성장 단계

| 단계 | 조건 예시 | 표현 |
| --- | --- | --- |
| 씨앗 | 첫 기록 | 작은 씨앗 |
| 새싹 | 누적 3회 | 두 잎 새싹 |
| 잎 | 누적 10회 | 취미별 잎 추가 |
| 화분 | 누적 30회 | 나만의 화분 |
| 작은 정원 | 장기 누적 | 여러 취미 식물 조합 |

### 11.3 UX 원칙

- 연속 기록이 끊겨도 식물이 시들지 않는다.
- 취미별 식물의 색·잎 형태를 구분하되 접근 가능한 라벨을 함께 제공한다.
- 성장 애니메이션은 600ms 이내, 다시 보기 가능, reduced-motion 지원.
- "이번 달 4번 기록해서 새잎이 자랐어요"처럼 결과와 원인을 함께 설명한다.
- MVP에서는 홈의 작은 성장 카드만 제공하고, 전체 정원은 P2로 분리한다.

## 12. 접근성·콘텐츠 가이드

- 본문 대비 4.5:1, 큰 텍스트·UI 그래픽 3:1 이상 목표
- 키보드만으로 작성·달력 이동·필터·삭제 가능
- 사진에는 사용자가 대체 텍스트를 선택 입력할 수 있게 검토
- 날짜는 "10월 24일 금요일", 별점은 "5점 만점에 4점"으로 읽히게 함
- 오류 문구는 원인 + 해결 행동으로 작성
- 친근하지만 유아적이지 않은 존댓말 사용
- 빈 상태 예: "아직 기록이 없어요. 오늘의 취미를 첫 잎으로 남겨보세요."
- 저장 완료 예: "기록을 저장했어요."
- 삭제 확인 예: "이 기록을 삭제할까요? 삭제 후에는 되돌릴 수 없어요."
